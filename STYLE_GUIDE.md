# Стиль файлов для расширения проекта

## Принципы
1. **Каждый файл — одна тема** с 5–15 связанными концепциями.
2. **Docstring в начале файла** перечисляет ВСЕ концепции в файле с кратким объяснением каждой (3-8 строк на концепцию). Это и есть учебный материал.
3. **Запускаемость**: `python путь/к/файлу.py` должен отработать БЕЗ ошибок и без интерактивного ввода.
4. **Зависимости**: только `numpy`, `matplotlib`, `scikit-learn`. Никакого pandas, torch, tensorflow, scipy.stats (если нужно — реализовать вручную) и т.п.
5. **Размер**: 40–120 строк на файл. Код компактный, без боилерплейта.
6. **Комментарии и docstring — на русском**.
7. **`print()` — итог, а не лог.** Выводим короткий результат, чтобы школьник увидел "что получилось".
8. **Никаких `plt.show()`** — закрывайте окна или используйте `matplotlib.use('Agg')` если рисуете; лучше просто не рисовать, а печатать числа.
9. **`np.random.default_rng(0)`** для воспроизводимости (или `random.seed(0)`).
10. **Никаких относительных импортов**, никаких `__init__.py`.

## Шаблон файла

```python
"""Раздел N — Название темы.

Концепция X: Название.
Короткое (3-6 строк) объяснение: что это, зачем, как работает, где используется.

Концепция X+1: ...
Концепция X+2: ...
...
"""
import numpy as np

# === Концепция X: ... ===
# короткое демо в 3-10 строк
...
print("X:", результат)

# === Концепция X+1: ... ===
...
print("X+1:", результат)
```

## Чего избегать
- НЕ создавать markdown-документы (кроме обновлений существующих).
- НЕ использовать эмодзи.
- НЕ делать "защитного" программирования (try/except для невозможных кейсов).
- НЕ писать длинных комментариев внутри кода — основной разбор в docstring.
- НЕ ставить `if __name__ == "__main__":` — пусть код просто выполняется в module-scope.
